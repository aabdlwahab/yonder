Edit the code where it runs.

Yonder is a desktop editor built on Zed. Your projects, terminals, builds and coding agents stay on your machines, over SSH, and keep working after you close the laptop.

here → over there

Open a project on any machine.

The window draws here. The files, language servers, terminals and builds stay over there and run on the machine itself, with no containers and nothing to sync.

Your machines can be Linux or macOS. Yonder itself runs on a Mac or an Ubuntu desktop.

agents · on each machine

Put an agent next to the code.

Claude Code and Codex run on the machine that holds the project, so they read the real files and run the real tests. A machine can have several Claude accounts signed in, and any thread can use any of them.

lid shut · the hub carries on

The threads keep going after you close the laptop.

One always-on machine is the hub. It starts the agents, keeps every thread's history, and holds each agent's questions until someone answers. Open the laptop again and the threads are further along.

phone · you decide

Answer from your phone.

When an agent wants to run something, your phone says so. Tap it, read the exact command and approve it there. Or ask Dispatch, out loud, what everything is doing.

over there

Switch projects without waiting for them.

The fleet panel lists your machines, and under each one the projects you've opened there. Click one and it opens in the same window. Try it on the right.

4 open

Each window keeps four projects open, so going back to one of them doesn't reconnect. The green dots on the right are the four it's keeping.

250 ms

Rest the pointer on a project and its machine's SSH connection opens before you click.

⌃⌘K

Search every project on every machine, and recent threads, from the keyboard.

addresses

Give a machine more than one address, like its office IP and its Tailscale name. Yonder uses whichever answers, and moves when you change networks.

On a Mac or an Ubuntu desktop.

It's the same Yonder on both, with the same fleet, threads and hub. The machines you connect to can be either too, so an Ubuntu workstation can edit code on a Mac mini and the other way round.

macOS

An app in Applications. The hub's token goes in your Keychain. ⌃⌘K searches every project.

Ubuntu

Installs in your home folder with a menu entry, no sudo. Wayland or X11. The token goes in your keyring. ctrl-alt-k searches.

hand off

A thread can change hands and keep its memory.

Run out of usage on one Claude account and carry on under another. Hand the conversation to Codex. Fork it from any message into its own git worktree, or forward one message to another thread. Each move keeps everything that was said.

Ask what everything is doing.

Dispatch is the hub's assistant. It can see every thread on every machine, read them, and pass a message to any thread's agent for you. Type to it from the Mac or talk to it on your phone.

approve

Nothing runs on its say-so. It reads the exact command back, and approves only after you say so yourself.

notify

Your phone hears about it when a thread needs an answer, a long turn finishes, or an agent stops.

install

Add it to your Home Screen and it opens like an app, straight into the thread that needs you.

private

Only inside your Tailscale network. The hub serves the page itself, and a phone has to be paired before it sees anything.

one program

One program on every machine.

The app, the server each machine runs, and the hub are the same yonder program. On a Mac or an Ubuntu desktop it's the app itself. A Linux server gets one static file that runs on any distribution, with no display libraries and nothing to install first.

yonder

The editor, the fleet panel and the agent panel, on your Mac or Ubuntu desktop.

yonder server

What the app starts over SSH on each machine your code lives on.

yonder hub serve

The always-on machine that owns the threads and runs Dispatch.

Build it on your computer.

          

            There are no release downloads yet. Yonder builds like Zed, so set up Rust and the
            system packages with Zed's guide for
            macOS or
            Linux,
            then run the install script. A release build takes twenty minutes or so.
          

          

            

              
On a Mac

              
Builds the app, signs it for this Mac and installs it in Applications. -l also builds the program for your Linux machines on one of them.

              

                
Terminal


$ git clone https://github.com/aabdlwahab/yonder.git
$ cd yonder
$ script/install-mac -l build-box

              

            

            

              
On Ubuntu

              
Installs the build packages (this step asks for sudo), then builds Yonder and installs it in ~/.local with a menu entry.

              

                
Terminal


$ git clone https://github.com/aabdlwahab/yonder.git
$ cd yonder
$ script/linux
$ script/install-linux

              

            

          

          

            No build tools on your Ubuntu machine? script/build-linux-docker build-box
            builds it in a container on any machine with Docker, and
            script/install-linux yonder-linux-x86_64.tar.gz installs the result. Then add
            your machines in Settings → Machines; Yonder installs itself on each one the first time
            you open a project there. The Mac app isn't signed with an Apple Developer ID, so a
            build runs on the Mac that made it.
