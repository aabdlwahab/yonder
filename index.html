a native editor for code on other machines

Your code lives over there. Work on it from here.

Yonder is a native desktop editor built on Zed. Your laptop draws the window. Projects, language servers, terminals, builds and coding agents run on your machines over SSH, keep running when you close the laptop, and find you on your phone when they need you.

Get Yonder Source on GitHub

Open source under GPL-3.0. A macOS app, for Linux and macOS machines. No account, no telemetry, no Yonder cloud: everything runs on machines you already have.

machines, then projects

Every machine you work on, in one sidebar.

The fleet panel lists your SSH machines, and under each one the projects you have opened there. Pick a project and it opens in the same window. Nothing runs in a container: the project is a folder on the machine, and its language servers, terminals and builds run there directly.

01

Switching is instant

Each window keeps four projects open, so going back to one of them doesn't reconnect. Resting the pointer on a project opens its SSH connection before you click.

ctrlcmdK
02

Any address that answers

Give a machine several addresses, like its office IP and its Tailscale name. Yonder tries them in order, and when you change networks it moves to the one that works.

03

What needs you, first

An Active group at the top shows threads that are waiting for an approval, then the ones that are running, then the ones with something new to read.

agents where the code is

Claude Code and Codex, on every machine.

Agent threads run on the machine that holds the project, so they read and build the real code. Each machine can have several Claude accounts signed in, and a thread can move between accounts and agents without losing what was said.

CONTINUE

Continue as another account. Hit a usage limit and pick up the same conversation under another Claude account.

HAND OFF

Hand a thread to another agent. Codex gets the conversation so far and carries on.

FORK

Fork from any message. Forks run side by side, each in its own git worktree, so they don't step on each other.

FORWARD

Forward a message to a new thread or to one that is already running.

GUESTS

Tag another agent into a thread with @. Guests start read-only, and their answers come back to the thread's own agent with your next message.

close the laptop

Threads keep going without you.

Pick one always-on machine as the hub. It owns your agent threads: it starts the agents on each machine, keeps every thread's history, and holds approvals until you answer. The Mac app and your phone are both windows onto it, so you can close one and carry on in the other.

01

Turns finish anyway

A long refactor or test run keeps going after you close the laptop. Open Yonder again and the thread is where the agent left it.

02

Approvals wait for you

When an agent asks to run something, the hub holds the question, and the first answer from the app, the phone or the command line wins.

03

Restarts lose nothing

The hub keeps each thread's log on disk. After a restart, threads resume with their history and the agent remembers the conversation.

talk to all of it

Ask Dispatch.

Dispatch is an assistant that knows every thread on every machine. Ask it from the Mac, or talk to it from your phone. It answers out loud, and it can pass a message to any thread's agent for you.

  • What's happening? It lists threads, reads them, and tells you what each agent is doing right now.
  • Tell the trainer thread to stop after this epoch. Messages go straight to that thread's agent, or wait their turn if it's busy.
  • Approvals only on your word. Dispatch reads the exact command back, and nothing runs until you say approve.
  • On your Home Screen. The phone page installs as an app, with notifications when a thread needs you, a long turn finishes, or an agent stops.

The phone page is served by your hub, only inside your Tailscale network, and a phone has to be paired before it can see anything.

one program on every machine

The same yonder does every job.

The app, the server each machine runs, and the hub are one program. On a Mac it is the app itself. Servers get a single static Linux file that runs on any distribution, with no display libraries and nothing to install first.

APP

Yonder.app on your Mac: the editor, the fleet panel and the agent panel.

MACHINE

yonder server: what the app starts over SSH on each machine your code lives on.

HUB

yonder hub serve: the always-on machine that owns threads, runs Dispatch and serves the phone page.

the hub from any terminal
$ yonder hub list
$ yonder hub run --machine gpu-a --agent codex-acp --cwd ~/trainer "Summarise the last eval"
$ yonder hub follow 3f2a91c0
$ yonder hub approve 3f2a91c0

yours, end to end

Nothing goes anywhere you didn't send it.

01

No phoning home

Telemetry and crash-report uploads are off whatever the settings say. Update checks and Zed sign-in are disabled.

02

Your machines, your accounts

Agents use the Claude and Codex sign-ins already on each machine. There is no Yonder service in the middle.

03

Beside Zed, not instead of it

Yonder has its own name, settings and data folders, so it installs next to Zed without sharing anything.

get yonder

Build it on your Mac.

There are no release downloads yet, so Yonder is built from source. It builds like Zed: follow Zed's macOS guide for the toolchain, then run the install script. The release build takes about twenty minutes.

The Mac app

Builds Yonder in release mode, signs it for this Mac, and installs /Applications/Yonder.app.

on your Mac
$ git clone https://github.com/aabdlwahab/yonder.git
$ cd yonder
$ script/install-mac

The program for Linux machines

Builds the static yonder program on a Linux machine. -l builds it there over SSH and puts it inside the app.

on your Mac
# build-box: any Linux machine with Rust and zig
$ script/install-mac -l build-box

Then add your machines in Settings → Machines, or as ssh_connections in your settings file. The app installs its server on each machine the first time you open a project there. Yonder isn't signed with an Apple Developer ID, so it only runs on the Mac that built it.

Work on every machine from one window.

Your projects stay where they run. Your agents keep working when you leave. Yonder brings both to the window in front of you.
